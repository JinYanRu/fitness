# Fitness OCR 营养管理 App - 开发计划

## 项目愿景

打造一个智能饮食管理应用，通过 OCR + AI 大模型技术，让用户轻松记录和追踪每日饮食营养摄入，实现科学的增肌/减脂目标。

---

## 二、核心功能模块设计

### 2.1 食物管理模块（基础数据层）

#### 功能一：营养成分表拍照录入（用户私有数据）

**场景**：用户购买包装食品，通过拍摄营养成分表快速录入食物信息。

**流程**：
1. 用户拍摄/选择营养成分表照片
2. 调用 OCR 服务识别文字
3. 调用大模型解析营养成分（能量、蛋白质、脂肪、碳水等）
4. 用户确认/编辑后保存到「我的食物库」
5. 数据标记为用户私有（user_id）

**已实现**：OCR 识别流程 ✅
**待开发**：食物库存储、用户关联

#### 功能二：自定义菜谱录入（用户私有数据）

**场景**：用户自制菜品（如鸡胸肉丸子），想记录整道菜的营养成分。

**流程**：
1. 用户输入菜谱名称
2. 添加原材料（支持拍照/文字）
   - 方式 A：拍摄原材料照片 → OCR 识别 → 选择匹配的原材料
   - 方式 B：手动搜索选择原材料
3. 输入各原材料用量
4. 系统自动计算整道菜的营养成分（原材料营养求和）
5. 用户确认后保存到「我的食物库」

**数据模型**：
```
recipe (菜谱)
├── id, user_id, name, servings, total_weight
├── calories, protein, fat, carbohydrates...
└── create_time

recipe_ingredient (菜谱原料)
├── id, recipe_id
├── food_id (关联 food_nutrition 或 user_food)
├── amount, unit
└── calories, protein... (冗余存储，方便查询)
```

**待开发**：完整功能

#### 功能三：公共食物库（全局共享数据）

**场景**：常见食物（米饭、土豆、番茄等）的营养数据，所有用户共享。

**数据来源**：
1. 官方预置数据（中国食物成分表）
2. 用户上传数据经审核后共享
3. 爬取权威营养数据库

**数据模型**：
```
common_food (公共食物库)
├── id, name, category, brand
├── serving_size, serving_unit
├── calories, protein, fat, saturated_fat
├── carbohydrates, fiber, sodium, sugar, calcium
├── source (official/user_upload/crawled)
├── verified (是否人工审核)
└── create_time, update_time
```

**待开发**：完整功能

### 2.2 饮食记录模块

#### 功能：每日饮食打卡

**场景**：记录用户每天吃了什么、吃了多少。

**流程**：
1. 用户从三种食物来源中选择：
   - 我的食物库（私有食物/菜谱）
   - 公共食物库
   - 新建食物（跳转到食物管理）
2. 输入食用量
3. 选择用餐类型（早餐/午餐/晚餐/加餐/健身餐）
4. 可选：添加备注
5. 保存到当日饮食记录

**数据模型**：
```
daily_record (每日饮食记录)
├── id, user_id, record_date
├── meal_type (breakfast/lunch/dinner/snack/workout)
├── food_id, food_type (common/user/recipe)
├── food_name (冗余存储)
├── serving_amount, serving_unit
├── calories, protein, fat, carbohydrates... (计算后的实际摄入)
├── remark
└── create_time

daily_summary (每日汇总，可选优化)
├── id, user_id, record_date
├── total_calories, total_protein...
└── update_time
```

**待开发**：完整功能

### 2.3 营养分析模块

#### 功能一：每日营养摄入统计

**场景**：实时展示当日营养摄入情况。

**展示内容**：
- 总热量摄入 vs 目标热量
- 三大营养素（蛋白质/脂肪/碳水）摄入比例
- 微量营养素（膳食纤维/钠/糖/钙）摄入
- 摄入不足/超标的营养素高亮提示

**数据来源**：
- 实时计算 `daily_record` 汇总
- 用户目标来自用户配置

**待开发**：完整功能

#### 功能二：AI 营养分析报告

**场景**：用户想了解今日饮食是否合理。

**流程**：
1. 用户点击「AI 分析」按钮
2. 系统汇总当日所有饮食记录
3. 调用大模型，传入：
   - 用户信息（年龄/体重/身高/性别/目标）
   - 当日饮食记录
   - 营养目标
4. AI 返回分析报告：
   - 今日饮食评价
   - 营养均衡建议
   - 改进方向

**待开发**：完整功能

#### 功能三：历史数据趋势

**场景**：查看过去一段时间的饮食趋势。

**功能**：
- 周/月营养摄入趋势图
- 平均营养摄入统计
- 达成目标的天数统计

**待开发**：完整功能

### 2.4 用户管理模块

#### 功能：用户配置与目标设定

**用户信息**：
- 基础信息：昵称、头像、性别、生日
- 身体数据：身高、当前体重
- 目标设置：增肌/减脂/维持
- 活动水平：久坐/轻度活动/中度活动/高强度活动

**计算逻辑**：
1. 根据用户信息计算 BMR（基础代谢率）
2. 根据活动水平计算 TDEE（每日总能量消耗）
3. 根据目标调整热量建议（增肌 +10%，减脂 -20%）
4. 计算三大营养素推荐摄入比例

**数据模型**：
```
user_profile (用户档案)
├── id, user_id (关联用户系统)
├── nickname, avatar, gender, birthday
├── height, weight, target_weight
├── goal (muscle_gain/fat_loss/maintain)
├── activity_level (sedentary/light/moderate/high)
├── bmr, tdee (计算值，可缓存)
├── target_calories, target_protein, target_fat, target_carbs
└── create_time, update_time
```

**待开发**：完整功能

### 3.2 数据库设计

```sql
-- 用户表
CREATE TABLE user (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(64) UNIQUE,
    password_hash VARCHAR(256),
    nickname VARCHAR(64),
    avatar VARCHAR(256),
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 用户档案表
CREATE TABLE user_profile (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT UNIQUE,
    gender TINYINT COMMENT '1-男, 2-女',
    birthday DATE,
    height DECIMAL(5,2) COMMENT '身高(cm)',
    weight DECIMAL(5,2) COMMENT '体重(kg)',
    target_weight DECIMAL(5,2),
    goal VARCHAR(32) COMMENT 'muscle_gain/fat_loss/maintain',
    activity_level VARCHAR(32) COMMENT 'sedentary/light/moderate/high',
    target_calories INT,
    target_protein DECIMAL(10,2),
    target_fat DECIMAL(10,2),
    target_carbs DECIMAL(10,2),
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES user(id)
);

-- 用户私有食物库
CREATE TABLE user_food (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    food_name VARCHAR(128) NOT NULL,
    brand VARCHAR(64),
    serving_size DECIMAL(10,2),
    serving_unit VARCHAR(16),
    calories DECIMAL(10,2),
    protein DECIMAL(10,2),
    fat DECIMAL(10,2),
    saturated_fat DECIMAL(10,2),
    carbohydrates DECIMAL(10,2),
    fiber DECIMAL(10,2),
    sodium DECIMAL(10,2),
    sugar DECIMAL(10,2),
    calcium DECIMAL(10,2),
    source VARCHAR(32) DEFAULT 'ocr' COMMENT 'ocr/manual',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES user(id),
    INDEX idx_user_food (user_id, food_name)
);

-- 用户菜谱表
CREATE TABLE user_recipe (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    name VARCHAR(128) NOT NULL,
    servings INT DEFAULT 1,
    total_weight DECIMAL(10,2),
    calories DECIMAL(10,2),
    protein DECIMAL(10,2),
    fat DECIMAL(10,2),
    saturated_fat DECIMAL(10,2),
    carbohydrates DECIMAL(10,2),
    fiber DECIMAL(10,2),
    sodium DECIMAL(10,2),
    sugar DECIMAL(10,2),
    calcium DECIMAL(10,2),
    remark TEXT,
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES user(id)
);

-- 菜谱原料表
CREATE TABLE recipe_ingredient (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    recipe_id BIGINT NOT NULL,
    food_type VARCHAR(32) COMMENT 'common/user',
    food_id BIGINT COMMENT '关联 common_food 或 user_food',
    food_name VARCHAR(128),
    amount DECIMAL(10,2),
    unit VARCHAR(16),
    calories DECIMAL(10,2),
    protein DECIMAL(10,2),
    fat DECIMAL(10,2),
    carbohydrates DECIMAL(10,2),
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (recipe_id) REFERENCES user_recipe(id)
);

-- 每日饮食记录表
CREATE TABLE daily_record (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    record_date DATE NOT NULL,
    meal_type VARCHAR(32) COMMENT 'breakfast/lunch/dinner/snack/workout',
    food_type VARCHAR(32) COMMENT 'common/user/recipe',
    food_id BIGINT,
    food_name VARCHAR(128),
    serving_amount DECIMAL(10,2),
    serving_unit VARCHAR(16),
    calories DECIMAL(10,2),
    protein DECIMAL(10,2),
    fat DECIMAL(10,2),
    saturated_fat DECIMAL(10,2),
    carbohydrates DECIMAL(10,2),
    fiber DECIMAL(10,2),
    sodium DECIMAL(10,2),
    sugar DECIMAL(10,2),
    calcium DECIMAL(10,2),
    remark VARCHAR(256),
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES user(id),
    INDEX idx_user_date (user_id, record_date),
    INDEX idx_user_date_meal (user_id, record_date, meal_type)
);

-- 公共食物库（复用现有 food_nutrition 表，增加字段）
ALTER TABLE food_nutrition
ADD COLUMN category VARCHAR(32) COMMENT '食物分类',
ADD COLUMN serving_unit VARCHAR(16) COMMENT '份量单位',
ADD COLUMN is_active TINYINT DEFAULT 1 COMMENT '是否启用';
```

### 3.3 API 设计

#### 认证相关
```
POST   /api/auth/register          # 用户注册

```

## 五、技术债务 & 风险

### 5.1 当前技术债务

| 问题 | 影响 | 建议处理方式 |
|------|------|--------------|
| 敏感信息硬编码 | 安全风险 | 使用环境变量或 Vault |
| 前后端 API 不一致 | 功能无法使用 | 优先修复 |
| 无测试覆盖 | 质量风险 | 逐步补充测试 |
| UniApp/纯 H5 混用 | 维护困难 | 决定技术路线 |
| README 文档过时 | 新人上手困难 | 更新文档 |

### 5.2 风险评估

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|----------|
| OCR 识别准确率不足 | 中 | 高 | 增加用户手动编辑功能 |

## 七、附录

### 7.1 营养计算公式

**BMR（基础代谢率）- Mifflin-St Jeor 公式**：
```
男性: BMR = 10 × 体重(kg) + 6.25 × 身高(cm) - 5 × 年龄 + 5
女性: BMR = 10 × 体重(kg) + 6.25 × 身高(cm) - 5 × 年龄 - 161
```

**TDEE（每日总能量消耗）**：
```
TDEE = BMR × 活动系数
活动系数:
- 久坐 (sedentary): 1.2
- 轻度活动 (light): 1.375
- 中度活动 (moderate): 1.55
- 高强度活动 (high): 1.725
```

**目标热量**：
```
增肌: TDEE × 1.1 (+10%)
减脂: TDEE × 0.8 (-20%)
维持: TDEE
```

**三大营养素分配**：
```
增肌: 蛋白质 30% / 脂肪 25% / 碳水 45%
减脂: 蛋白质 35% / 脂肪 25% / 碳水 40%
维持: 蛋白质 25% / 脂肪 30% / 碳水 45%
```
